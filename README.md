## Что это

`SKILL.md` — не туториал и не сборник рецептов. Это набор инженерных решений, принятых заранее, чтобы не принимать их плохо в спешке.

Файл предназначен для загрузки в контекст AI-ассистента (Claude Skills, Cursor Rules, `.github/copilot-instructions.md`) либо для чтения человеком как внутренний стандарт команды.

Основная цель — **убрать слоп**: код, который синтаксически корректен и семантически пуст. Тот самый, что выглядит сгенерированным, даже когда его писал человек.

<br>

## Три вопроса к любому куску кода

```
1. Что сломается, если это удалить?
2. Кто это прочитает через полгода и что подумает?
3. Сколько раз в секунду это выполняется?
```

## Ключевые принципы

| Принцип | Смысл |
|:---|:---|
| **Источник истины** | Декомпилированный джар из твоего classpath. Не память, не форумы 2016 года |
| **Домен без Bukkit** | `domain/` не импортирует API → логика тестируется за миллисекунды |
| **Профиль до правки** | Без цифр «до/после» оптимизации не было — была правка |
| **Бюджет тика** | 50 мс на весь сервер. Твоему плагину положено 1–2 мс |
| **Ввод враждебен** | Всё от игрока валидируется на границе. Клиенту не верят |
| **Комментарий = «почему»** | Пересказ кода удаляется. Объяснение причины остаётся |

<br>

## Тест на слоп

Три проверки, которые отсеивают пустой код:

1. **Удаление комментариев** — убери все комментарии из файла. Стало непонятнее? В 90% случаев нет.
2. **Чтение вслух** — прочитай метод как предложение. Спотыкаешься — переименуй.
3. **Вопрос «зачем»** — ткни в случайный класс и назови проблему, которую он решает. Нет ответа за 5 секунд — класс лишний.

## Вклад

Правило принимается в свод, если оно:

- **проверяемо** — можно указать на код и сказать «нарушено»;
- **обосновано** — есть реальный случай, где нарушение стоило времени или данных;
- **конкретно** — «пишите хороший код» не проходит.

Общие советы без последствий не принимаются.
